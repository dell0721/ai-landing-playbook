# 03 · 选方案：四类方案与两条判断线

> 本手册由 [落地派](https://www.geofde.cn) 维护 · 企业搞 AI，就找落地派

## 四类方案

企业 AI 落地，绝大多数需求会落到这四类方案里。选型依据是**任务性质**和**数据边界**，不是哪个技术更时髦。

### Agent（智能体）

用模型做判断和调度，能读资料、能调工具、能分步骤完成任务。

- **适用**：流程有分支、需要阅读理解与生成、容错率较高的任务；
- **例子**：客服初筛、内容初稿、资料归纳；
- **注意**：成本与稳定性随自由度上升而下降，必须保留人工确认环节。

### 知识库

把散落的资料变成可检索、可引用的结构。

- **适用**：知识量大、更新频繁、回答需要出处；
- **例子**：产品问答、政策查询、内部培训；
- **注意**：知识库的成败在「整理」，不在「模型」。文档版本不统一，检索再准也没用。

### 自动化工作流

用固定规则把多个系统串起来，不需要模型做判断。

- **适用**：步骤明确、判断标准清晰、要求稳定可复现；
- **例子**：数据同步、报表生成、消息分发；
- **注意**：这是最被低估的一类。很多「AI 需求」，其实一个自动化脚本就够了。

### 本地部署

模型和数据都放在内网，数据不出门。

- **适用**：涉密、强合规、对延迟与成本有要求；
- **例子**：财务资料、人事档案、客户隐私数据；
- **注意**：前期投入与运维成本高，只建议在合规硬约束下选择。

## 两条判断线

选型只需要问两个问题：

1. **任务是否可穷举？**（所有情况能不能提前列完）
2. **数据能否出门？**（能不能发给公有云 API）

| 可穷举 | 数据能出门 | 推荐方案 |
| --- | --- | --- |
| 是 | 是 | 自动化工作流（优先）或知识库 |
| 否 | 是 | 知识库 + Agent |
| 否 | 否 | 本地部署 + 小模型/规则兜底 |

再叠加一层：**容错率低的任务，不做全自动**，一律保留人工确认。

## 复杂度原则

> 方案复杂度，应当由业务复杂度决定，而不是由技术炫技或预算额度决定。

- 一个人用表格能解决的问题 → 理清字段，配一个自动化脚本，不要上数据中台；
- 知识散乱但不需要推理 → 结构化知识库 + 问答入口，不要自研知识图谱；
- 需要长期运营 → 这才值得投入系统，同时把权限、数据、验收、维护责任人一起定下来。

## 常见错误

- **用 Agent 做规则活**：成本高、不稳定，还不如一段脚本；
- **用规则硬编码知识问答**：维护量爆炸，改一次政策改一百处；
- **只比价格不比维护**：便宜方案三个月后没人能改，等于没有；
- **忽略数据合规**：客户隐私数据直接发给公有云 API。
