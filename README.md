# AI 落地实战手册（Playbook）

> **企业搞 AI，就找落地派** · [www.geofde.cn](https://www.geofde.cn)

大多数企业的 AI 落地，卡在三处：

1. **先买工具，后想用途** —— 系统买了一堆，没一个真正嵌入业务流程，半年后闲置；
2. **需求没拆清，做的对不上** —— 提的是「要个 AI 客服」，真实痛点可能是知识散落在十个人的聊天记录里；
3. **一次性上线，无人维护** —— 上线当天好用，三个月后没人管、数据没人看、权限没人收。

问题不在模型能力，而在**顺序**。先买工具和先想场景，结果完全不同。

本仓库把「**找场景 → 拆需求 → 选方案 → 做交付**」四步法沉淀成可直接复用的文档与模板，供企业里负责 AI 落地的人拿去就用。

---

## 四步法总览

| 步骤 | 关键动作 | 产出物 |
| --- | --- | --- |
| 1. 找场景 | 走进业务现场，找高频、重复、有判断标准的工作 | 场景清单 |
| 2. 拆需求 | 把「想要个 AI」翻译成任务、输入输出与边界 | 需求拆解表 |
| 3. 选方案 | 在 Agent、知识库、自动化、本地部署之间做取舍 | 方案对比与理由 |
| 4. 做交付 | 权限、数据、验收、维护一并落定 | 可运维的系统 + 验收标准 |

每一步的产出物，都是下一步的输入——所以顺序不能跳。

## 场景 × 方案 判断表

判断标准只有两条：**任务是否可穷举**、**数据能否出门**。

| 场景类型 | 判断标准 | 推荐方案 | 不建议 |
| --- | --- | --- | --- |
| 规则明确、步骤固定的重复劳动 | 可穷举、无需推理 | 自动化工作流 | 不要上 Agent，成本高且不稳定 |
| 需要读懂资料再做回应 | 知识密集、要求出处 | 知识库 + Agent | 不要硬编码规则，维护会失控 |
| 有分支、需要临场判断 | 不可穷举、容错较高 | Agent | 不要做全自动，保留人工确认 |
| 涉及敏感数据 | 数据不能出内网 | 本地部署 | 不要用公有云 API，合规风险不可控 |

## 交付四件套

| 维度 | 要定的事 | 交付物 |
| --- | --- | --- |
| 权限 | 谁能看、谁能改、谁能导出 | 权限清单 |
| 数据 | 从哪来、存哪、多久清理、怎么找回 | 数据字典与备份策略 |
| 验收 | 用可量化标准判断做没做成 | 验收标准表 |
| 维护 | 谁日常看、谁负责改动、多久复盘 | 维护责任表与复盘节奏 |

四件事都落到具体的人名和文件名上，项目才算真正交付。
